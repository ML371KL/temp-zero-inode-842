# MOEX Radar (репозиторий 842)

Прогнозная панель по индексу МосБиржи: **машина состояний + медленный композит**, а не
торговый терминал. Ядро меняет знак примерно дважды в год, состояние — несколько раз в
год; оперативность нужна не ради скорости сигнала, а ради свежести картины и ворот
риска. Что именно считается и почему — `validation/VALIDATION.md` и
`validation/REGIME.md`: каждая формула там либо подтверждена на истории 2004–2026, либо
помечена как наблюдение без предиктивных претензий.

Живёт на <https://tzi-842.pages.dev>.

## Архитектура в десять строк

1. **Источники** — ISS МосБиржи, ЦБ, Минфин, Росстат, ОРФР, Polymarket и ручные вводы
   `inputs/*` (реестр рядов и лаги публикации: `pipeline/lib/registry.py`).
2. **Конвейер** (`pipeline/`, Python 3.12, только стандартная библиотека) считает панель
   → композит → состояния → мониторы и публикует `data.json` и `history/*` в бакет R2.
3. **Один писатель** — VPS 46.62.207.91 по systemd-таймерам. Право на запись держит лиз
   `lease.json` (`docs/CONTRACT.md` §5).
4. **Фолбэк-писатель** — GitHub Actions (`.github/workflows/fallback.yml`), включается
   только когда хартбит VPS протух.
5. **Страница** — статика в `web/`, Cloudflare Pages, проект `tzi-842`.
6. **Данные к странице** приходят не публикацией, а функцией `functions/data/[[path]].js`
   прямо из R2: белый список объектов, честный 404, `no-store`, `Last-Modified`.
7. **Форматы** — единственный источник правды `docs/CONTRACT.md`; правка формата = правка
   контракта + инвариант в `tests/`.
8. **Константы**, добытые валидацией (веса ядра, статистика ячеек, SLA) —
   `pipeline/lib/constants.py`; подгонка «на глаз» запрещена, только реколибровка.
9. **События** — переходы рынка (смена ячейки, разворот ядра, решение ЦБ) идут в
   журнал витрины, в телеграм панели и в ленту хаба NEXUS (`pipeline/lib/nexus.py`),
   каждое с разбором бесплатной модели (`pipeline/lib/commentary.py`). Отказы обвязки
   (протухший источник, потерянный лиз) в ленту НЕ попадают — они уходят в общий
   ops-канал панелей, туда же, куда мостик systemd → `dash-alert` шлёт падения прогонов.
10. **Проектные решения и расписания целиком** — `docs/ARCHITECTURE.md`.

## Как запустить локально

Ничего ставить не нужно: нужен Python 3.12 и (для фронта) `npx`.

```bash
# проверить обвязку и окружение, ничего не трогая
python pipeline/run.py --mode selftest

# конвейер: считает и складывает результат в STATE_DIR, в R2 не пишет
STATE_DIR=./.state python pipeline/run.py --mode daily --dry-run

# тесты и разбор — то же, что делает CI
python -m py_compile $(git ls-files '*.py')
PYTHONPATH="$PWD" python -m unittest discover -s tests -t . -v

# страница вместе с функциями (каталог статики и биндинг R2 берутся из wrangler.toml)
npx wrangler@4.119.0 pages dev
```

Без ключей `R2_*` прогон считает, но публиковать ему некуда. Локальный бакет у
`pages dev` пустой, поэтому `/data/data.json` честно отвечает 503 — это работающая
функция, а не поломка; живые данные смотреть на опубликованном адресе.

Роль писателя и его идентификатор конвейер берёт из окружения (`RADAR_WRITER`,
`RADAR_WRITER_ID`), а не из аргументов командной строки — см. `ops/env.example`.

## Как развернуть

**VPS (основной писатель).**

```bash
sudo bash ops/install-vps.sh            # идемпотентно, повторный запуск = обновление
sudo vim /usr/local/etc/moex-radar/env  # ключи R2 (шаблон и пояснения: ops/env.example)
sudo runuser -u dash -- /usr/local/sbin/moex-radar selftest   # видит ли конвейер бакет
sudo runuser -u dash -- /usr/local/sbin/moex-radar bootstrap  # первичное наполнение
```

Установщик заводит пользователя `dash`, клонирует репозиторий в `/srv/dash/repo-842`,
ставит обвязку `/usr/local/sbin/moex-radar` и шесть юнитов, включает три таймера:
витринный такт каждые 15 минут в торговом окне, суточный прогон в 16:05 и 20:55 UTC,
ежедневный опрос месячных источников в 09:00 UTC. Файл окружения не перезаписывается
никогда. Мостик тревог `/usr/local/sbin/dash-alert` — из соседнего репозитория
(839-data), общий для всех панелей машины.

**Cloudflare.** Секреты репозитория: `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`
(публикация сайта), `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY` (фолбэк-писатель),
`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` (по желанию). Переменные: `R2_BUCKET` (по
умолчанию `moex-radar`), `FALLBACK_MAX_AGE_MIN` (по умолчанию 150). Сайт публикуется
только при изменении кода — данные едут в R2 мимо Pages.

**Сторож.** Внешний cron-job.org раз в полчаса смотрит `Last-Modified` у
`/data/data.json` и при протухании дёргает `fallback.yml` через `workflow_dispatch`.
PAT с правом `Actions: write` общий с BTC-панелью и истекает около октября 2026.

## Где что лежит

| Путь | Что |
|---|---|
| `docs/` | контракт данных, архитектура, каталог индикаторов |
| `validation/` | замороженные артефакты исследования: почему считаем именно так |
| `pipeline/` | конвейер: `run.py`, `lib/`, `fetch/`, `compute/`, `publish.py`, `alerts.py` |
| `inputs/` | ручные вводы (консенсус по ставке, события, дивиденды) |
| `seed/` | стартовые ряды из валидации для первичного наполнения |
| `web/` | статическая страница (каталог публикации Pages) |
| `functions/`, `lib/` | функции Pages и их модули (в раздачу не попадают) |
| `ops/` | обвязка VPS: скрипт, юниты systemd, установщик, шаблон окружения |
| `tests/` | инварианты схемы и расчётов на замороженных фикстурах |

Даты внутри — UTC, на экране — МСК (UTC+3).
