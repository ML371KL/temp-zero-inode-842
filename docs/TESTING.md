# Тесты «MOEX Radar»

Только `unittest` из стандартной библиотеки — как и весь пайплайн (CONTRACT §0).
Ни pytest, ни моков из внешних пакетов: набор обязан запускаться на голой машине,
на VPS системным `python3` и на раннере сразу после `setup-python`.

## Как запускать

```bash
# из корня репозитория
python -m unittest discover -s tests -t . -v

# один файл
python -m unittest tests.test_states -v

# один тест
python -m unittest tests.test_core.TestHysteresis.test_sign_survives_the_wobble
```

`-t .` обязателен: он делает корень репозитория top-level-каталогом, иначе
`import pipeline...` из тестов не находит пакет. То же самое делает `PYTHONPATH=$PWD`
(так запускает CI); `tests/__init__.py` дополнительно подставляет корень в `sys.path`,
чтобы набор работал и при запуске из IDE.

В CI (`.github/workflows/ci.yml`) прогон обёрнут двумя проверками, которые важнее
самих тестов: пустой набор считается провалом (`Ran 0 tests` = «файлы перестали
находиться по маске»), и отдельный греп валит сборку, если тест смотрит на часы.

## Три правила набора

1. **Никаких «сегодня минус N».** Тест, отсчитывающий даты от текущего дня, зелен
   ровно до того дня, когда перестаёт им быть, и краснеет не от поломки кода, а от
   календаря. В соседней панели (838) набор становился зелёным только по субботам, и
   это выяснилось через месяц. Все даты в тестах фиксированные, ответы источников
   заморожены в `tests/fixtures/`, «сейчас» передаётся параметром (`now=`).
   Осознанное исключение помечается в строке комментарием `ci: allow-now`.
2. **В сеть не ходим.** Фетчеры проверяются подменой `pipeline.lib.http.get_bytes` —
   самого нижнего слоя. Так в тесте работают настоящие декодирование windows-1251,
   разбор JSON и постраничный обход ISS; подмена «сразу распарсенного словаря»
   проверяла бы последние десять строк парсера, а ломается обычно всё, что до них.
   Незамоканный URL — это `AssertionError`, а не тихий поход наружу.
3. **Каждый инвариант привязан к мутации.** У проверок стоит комментарий вида
   «мутация: … → тест краснеет»: если сформулировать поломку, которую тест ловит,
   не получается, тест не нужен.

Модули пишут параллельные агенты, поэтому отсутствующий модуль даёт `skipTest` с
внятной причиной, а не падение: красный набор из-за ненаписанного файла обесценивает
красный цвет вообще. Помощники — `tests/need()` и `tests/need_any()`.

## Что осознанно НЕ покрыто

* **Сетевые фетчеры целиком.** Проверяется разбор ответов, а не то, что ISS/ЦБ/FRED
  сегодня отвечают тем же. Живой контракт источника ловится прогоном, а не тестом:
  тест, ходящий в сеть, краснеет от чужого релиза и приучает игнорировать красный.
* **R2 (`lib/r2.py`) и публикация в бакет.** Подпись SigV4 и обратная вычитка
  проверяются только реальным бакетом; в наборе живёт лишь логика лиза.
* **Telegram-уведомления.** Отправка — побочный эффект без возвращаемого значения;
  дедуп событий появится в наборе вместе со стабилизировавшимся `alerts.py`.
* **Фронт (`web/`).** Разбирается `node --check` в CI; поведения браузера здесь нет.
* **PDF-слой ОРФР.** Фикстура — уже извлечённый ТЕКСТ обзора: распаковка потоков и
  CMap шрифтов проверяются на живых PDF в `validation/`, а не в юнит-наборе.
* **Числа валидации.** Тесты проверяют, что пайплайн считает по описанным правилам,
  и НЕ переспорят `validation/`: константы (`CELL_STATS`, веса, пороги) меняются
  только реколибровкой, тесты лишь фиксируют их применение.

### Как устроен `panel_small.json`

Ряды заданы правилами, а ответы в блоке `expect` выведены **из правил**, а не из кода
пайплайна (иначе тест сверял бы код с самим собой). Календарь: рабочие дни с
2024-01-09 без праздников РФ, 300 дней, последний — 2025-03-24.

| Колонка | Правило |
|---|---|
| `imoex` | `3000 + 2i` при `i < 200`, дальше `5400 − 10i` (разворот в снижение) |
| `ma200` | `2863 + 0.5i` — медленно растущая средняя |
| `realized_vol_21` | `0.16…0.18` при `i < 250`, дальше линейный рост `0.30 → 0.35` |
| `vol_thresh80` | `0.28` (порог 80-го перцентиля) |
| `rgbi_dd` | `−0.004…−0.006` при `i < 180`, дальше линейно до `−0.052` |
| `key_rate` | `16 → 18` на `i = 100`, `18 → 17` на `i = 200` |

Отсюда точки переключения (они и лежат в `expect.since_index`):

* `i = 242` — индекс уходит под MA200 (`5400 − 10i < 2863 + 0.5i` впервые), тренд 1 → 0;
* `i = 250` — вола перескакивает 0.28, флаг стресса 0 → 1;
* `i = 264` — просадка RGBI впервые глубже −4 % (на `i = 263` она −3.9983 %), флаг 0 → 1;
* `i = 200` — последнее изменение ключевой ставки вниз, фаза = смягчение (−1).

Последний день даёт ячейку **(медведь, стресс, стресс)** = `bear|stress|stress`,
−2,94 %/мес, n = 25, hit 0,56 — та самая токсичная ячейка из REGIME.md §2, и ровно
на ней проверяются ворота сигналов второго ряда: включены `mom63`, `switch_spread`,
`rb_gap`, `dy_trail`, `rgbi_mom21`; выключены `dd252` (нужен спокойный RGBI) и
`futoi_z120` (нужен спокойный бык).

Числа последнего дня подобраны круглыми, чтобы расстояния до порогов сверялись
литералами: индекс 2410 против средней 3012.5 = −20,0 %; вола 35,0 % против порога
28,0 % = +7,0 п.п.; просадка RGBI −0,052 в ЛОГ-мере (на ней стоит бит и `CELL_STATS`)
= −5,1 % на витрине при пороге −3,9 % = 1,1 п.п. запаса. Витрина и бит меряют одно и
то же разными мерами намеренно: `value`/`threshold` переводятся парой через
`exp(x)−1`, поэтому момент переключения флага не сдвигается, а подпись перестаёт
завышать глубину падения ОФЗ (в 2022-м лог-мера давала −37,5 % против −31,3 %).

Фикстура сгенерирована по этим правилам; при изменении правил меняются и `expect`,
и таблица выше — вместе, одной правкой.
