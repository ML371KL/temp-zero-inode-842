# Архитектура дашборда «MOEX Radar» (репо 842)

Дата: 2026-08-11. Дизайн под имеющуюся инфраструктуру: GitHub (repo `temp-zero-inode-842`) + Cloudflare Pages (`tzi-842.pages.dev`) + R2 (данные) + VPS 46.62.207.91 (вычислитель). Реализует четырёхслойную модель из `validation/REGIME.md`: эра → ядро-композит → машина состояний → мониторинг событий и потоков.

---

## 1. Принципы (выводы валидации, зашитые в дизайн)

1. **Дашборд — не сигнальная машина на каждый день, а машина состояний + медленный композит.** Ядро меняет знак ~2 раза в год; состояние меняется несколько раз в год. Значит: оперативность нужна не для скорости сигнала, а для (а) свежести картины, (б) событийных дней (ЦБ, ОРФР), (в) ворот риска (облигационный флаг). Интрадей — только витрина; официальный пересчёт — по закрытиям.
2. **Один писатель.** В R2 пишет только VPS. GitHub Actions — фолбэк-писатель, активируется ТОЛЬКО если хартбит VPS протух (лиз-объект в R2). Урок IBKR-аудита: два писателя = гонки.
3. **Канарейка внутри данных.** Каждый объект data.json несёт `generated_at`, `sources:{name:{asof, fetched_at, status}}`; фронт красит протухшие тайлы. Отдельно — сквозная проверка доставки (страница показывает возраст данных крупно).
4. **Честные лаги публикации** — те же, что в валидации: сигнал в панели датируется днём доступности (ОРФР +15, ИПЦ +13, Urals +5, декады +4). Никаких «подсмотренных» значений в витрине.
5. **Разделение «скоринг vs мониторинг».** Слои 1–2 дают числа и вердикты (валидированы). Слой 3 — только факты и графики, без предсказательных претензий (бейдж «monitor», как решено в VALIDATION.md).
6. **Модель может умереть.** Встроенный model-health: скользящий 24-мес IC композита; при уходе ниже нуля — жёлтый статус модели и алерт (не молчаливая деградация).

## 2. Топология

```
[Источники] ──> VPS (питон-пайплайн, systemd-таймеры)
                 │  fetch/ (кэш сырья в R2: raw/{source}/...)
                 │  signals (панель → композит → состояния → тайлы)
                 │  publish (лиз → data.json, history/*.json в R2)
                 │  alerts (Telegram при сменах состояний/знаков)
                 ▼
        R2 bucket moex-radar
                 ▲                        ▲
    GH Actions (фолбэк-писатель,          │
    активен только при протухшем лизе)    │
                                          │
Cloudflare Pages tzi-842 ── functions/data/[[path]].js ── читает R2
Браузер ── статический фронт ── /data/data.json (+ history шарды)
cron-job.org ── (1) пинг VPS-эндпоинта живости, (2) триггер fallback-workflow при протухании
```

- **VPS — primary compute.** Уже держит IBKR-пайплайн; добавляется юнит `moex-radar.timer/service` (venv, `pipeline/run.py --mode=...`). Все RU-источники отвечали в тестах на зарубежный IP (проверено из Малайзии); на случай геоблока каждого фетчера — фолбэк-цепочка (см. §4).
- **GitHub repo 842**: код пайплайна, фронт, `inputs/` (ручные вводы), workflows (deploy Pages; fallback-pipeline по cron+dispatch; recalibrate quarterly). Данные в git НЕ живут (только в R2) — кроме `inputs/` и снапшота `validation/` (замороженные артефакты исследования: panel_long, ic_results, VALIDATION/REGIME.md).
- **R2 структура**:
  - `data.json` — горячий компакт (≤200 КБ): всё для первого экрана.
  - `history/daily.json` — дневные ряды для графиков (композит, состояния, IMOEX, RGBI, компоненты; 2004+ прореженно, 2020+ полно).
  - `history/monitors.json` — ряды слоя 3 (ОРФР, LQDT, депозиты, дивкалендарь…).
  - `raw/{source}/{date}.json|csv` — кэш сырья (инкрементальные дозагрузки, восстановимость).
  - `lease.json` — {writer, heartbeat_ts}; `events.log` — журнал алертов/смен.

## 3. Вычислительное ядро (pipeline/)

Портируется из `validation/` (тот же код, отрефакторенный в модуль):

- `panel.py` — инкрементальная сборка длинной панели: дочитывает только новые дни из raw-кэша, пересчитывает хвост сигналов (rolling-окна требуют максимум 504 дня хвоста — полный пересчёт панели всё равно секунды, можно и не оптимизировать).
- `core.py` — слой 1: z-скоры (rolling 60м, clip ±3) → композит = mean(z(usd_mom63), z(slope_10_2) [, −z(urals_rub_gap) — флагом, по умолчанию вкл. с бейджем «не защищена»]). Гистерезис знака ±0,1 для алертов.
- `states.py` — слой 2: тренд (close vs MA200), вола (21д реализованная > P80 за 756д), облигации (RGBI dd < −4%), фаза ставки (знак последнего изменения). Ячейка + историческая статистика ячейки (из REGIME.md, зашита константами) + активные сигналы второго ряда по ячейке (mom63 в стрессе, dd+bond-фильтр, switch_spread в смягчении, futoi в спокойном быке).
- `monitors.py` — слой 3: тайлы без скоринга (см. §5).
- `events.py` — событийный режим дня ЦБ: в 13:25–14:00 МСК опрос cbr.ru/press/keypr каждые 2 мин; решение + `inputs/consensus.yml` → вердикт «довиш/хокиш/в линию» → алерт.
- `health.py` — model-health (trailing 24м IC композита по факту), канарейки источников, SLA.
- `publish.py` — сборка data.json/history, захват лиза (CAS: читает lease, пишет со своим id, перечитывает), запись, обновление heartbeat.
- `alerts.py` — телеграм по образцу notify.mjs 837/838 (события: см. §6).

Всё — Python 3.11 + pandas + requests; никаких тяжёлых зависимостей. Полный дневной прогон < 30 сек.

## 5. Фронт (Cloudflare Pages, статика + functions/data-прокси в R2)

Один экран, сверху вниз:

1. **Шапка-вердикт**: ячейка машины состояний (3 бита + фаза ставки) крупно, историческая статистика ячейки (средний fwd-месяц, hit), композит-гейдж (−3…+3) со стрелкой и правилом дня («токсичная ячейка: покупать подтверждение»; «вола-шип при спокойном RGBI: окно входа»). Возраст данных.
2. **Слой 1 — ядро**: три компонента (z, спарклайн 2 года, подпись механизма), композит-лента с 2004 (фон = знак), отметки смен знака; тайл model-health (trailing IC 24м).
3. **Слой 2 — машина состояний**: лента состояний с 2004 (цветные полосы: токсичные/покупаемые эпизоды), текущие расстояния до переключений («RGBI в −4,1% от максимума → флаг снимется при +0,7%»; «индекс −3,2% до MA200»), активные сигналы второго ряда для текущей ячейки.
4. **Слой 3 — мониторы** (сетка тайлов, каждый с бейджем tier из валидации: A/B/monitor/☠): потоки ОРФР (стек по категориям + метрика исчерпания продавца), LQDT-комплекс (СЧА + дневной поток; тайл «Большая ротация: ещё не случалась»), декадные депозиты vs дивдоходность (spread-переключатель), дивкалендарь сезона (выплачено/впереди/оценка реинвеста), заседание ЦБ (обратный отсчёт, консенсус, RUSFAR−ключ «что в цене»), недельный ИПЦ + SAAR, аукционы ОФЗ (bid-to-cover, флаг провала), Polymarket (уровень+дельта), FUTOI (z-120 + число держателей), RVI, рублёвая бочка (налоговая + интрадей-прокси vs бюджетная 5440), сентябрьский узел (сезонный бейдж с 15.09).
5. **Журнал**: лента алертов/смен состояний/событий из events.log.

Фронт без сборщика (vanilla JS + лёгкий чарт, как в 837/838), тёмная тема, mobile-first (пользователь смотрит с телефона).

## 6. Алерты (Telegram, по образцу notify.mjs)

Шлются при СМЕНЕ, не по расписанию:
1. Композит пересёк 0 (с гистерезисом ±0,1) — «ядро развернулось».
2. Смена ячейки состояния; отдельно выделенно — установка/снятие облигационного флага и вход в «окно покупки» (вола=1, облигации=0).
3. День ЦБ: решение vs консенсус (довиш/хокиш/в линию) + напоминание за день «внеси консенсус».
4. ОРФР вышел: сводка потоков + метрика исчерпания ДУ.
5. Провал аукциона ОФЗ; первая декада роста ставок вкладов после серии снижений.
6. Санитарные (только пользователю, не в канал): протухание источника сверх SLA, потеря лиза, model-health < 0.

## 7. Надёжность и эксплуатация

- **systemd** на VPS: `moex-radar-intraday.timer` (15 мин, 10:00–23:50), `moex-radar-daily.timer` (19:05, 23:55), `moex-radar-monthly.timer` (утренний поллинг окон). Уроки claude-remote/systemd учтены: абсолютные пути, свой venv, `Restart=on-failure`.
- **cron-job.org** (существующий аккаунт): (1) каждые 30 мин GET `https://tzi-842.pages.dev/data/data.json` → если `generated_at` старше 2 ч в торговое время — дёргает GitHub `workflow_dispatch` fallback-pipeline (тот же код, но пишет только при протухшем лизе). ⚠️ PAT Actions:write истекает ~окт-2026 — общий с BTC-дашбордом риск, обновить один раз для всех.
- **CI**: тесты на фиксированных датах (никаких «сегодня минус N»), инварианты схемы data.json, смок парсеров на замороженных фикстурах страниц; ревью диффа перед пушем — обязательная практика.
- **Реколибровка**: квартальный workflow (ручной запуск) — дозбор данных, пересчёт IC ядра и walk-forward на удлинённой истории, отчёт-дифф в PR; годовая полная ревалидация. Пороговое правило пересмотра состава ядра: только при model-health<0 два квартала подряд И наличии механизма у кандидата (не по трейлинг-IC — этот путь доказанно ведёт в шум).
- **Первичное наполнение**: raw-кэш заливается из `validation/data/` (уже скачанные 2004–2026) — пайплайн со дня 1 работает в инкрементальном режиме.

## 8. Что сознательно НЕ делаем (v1)

- Не тянем ALGOPACK (бесплатного T−14 FUTOI + дневного скрейпа хватает; подписку можно добавить позже одним фетчером).
- Не строим NLP-сентимент и автопарсинг новостей (слой 3 ручной через inputs; дорого и не валидировано).
- Не делаем интрадей-пересчёт композита и никакого «трейдинг-терминала» — модель месячная, витрина живая.
- Не оптимизируем веса ядра (равные; оптимизация на этих n — самообман, зафиксировано в валидации).
