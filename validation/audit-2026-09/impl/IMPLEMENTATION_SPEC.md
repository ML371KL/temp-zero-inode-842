## 4. Решение (`pipeline/compute/decision.py`, НОВЫЙ) — IMPL-1

`daily_composite(panel, mf)`: дневной ряд композита «как compute_core, если бы сегодня был любой день истории»: для дня t в месяце M — по каждой ноге окно = raw-значения закрытых месяцев до M (не больше 59, только не-None) + значение ноги в день t; z = (v − mean)/sd (ddof=1), min 24 точки, обрезка ±3; композит = среднее знак×z по доступным ногам (n_used). На последний торговый день закрытого месяца обязан совпадать с `mf["composite"]` (≤1e-9). Ряд может быть O(дней×60) — допустимо (7 тыс. дней).

`compute_decision(panel, mf, states)` → блок `position`:
- дни решения: последний торговый день каждой календарной недели (ISO-неделя; неделя = period W-FRI, т.е. последний торговый день ≤ пятницы);
- знак: `comp_state ∈ {+1, −1, 0}` обновляется ТОЛЬКО в день решения по дневному композиту: `v > +thr → +1`, `v < −thr → −1`, иначе прежний;
- ворота: `gate_open = not (trend==0 and vol==1 and bond==1)` по гистерезисным битам, каждый день; если любой бит None — ворота считаются закрытыми (как P_lib: cell_ok);
- целевая позиция: `LONG` если `gate_open and comp_state == +1`, иначе `FLAT`;
- автомат: из LONG → FLAT при `not want` в ЛЮБОЙ день (причина: `gate_close` если ворота закрылись, иначе `comp_neg` — только в день решения); из FLAT → LONG при `want` в любой день (вход по воротам любым днём; причина `gate_open`, `comp_pos` или `entry`). До 2004-01-06 позиция не считается (start), состояние знака до старта копится.
- Обязана воспроизвести `impl/decision_fixture.json`: `P2_pos_rle`, `P2_trend/vol/bond_rle`, `P2_comp_state_rle`, `comp_live_tail` (≤1e-6), `P2_reasons` с 2018 — тест `tests/test_decision.py` сверяет ВСЁ это на боевом сторе (тест пропускается с явным skip-сообщением, если `STATE_DIR` не задан или стор пуст; в CI использовать фикстуру-панель из существующих тестов для синтетических проверок автомата: гистерезис, недельный такт, выход любым днём).
